# 0.1.0 plan — hyperspace crossing sim, path-finding difficulty modes

Goal (from README draft): hyperspace is a parallel, smaller-scale universe. Crossing it is the
hard part — the project investigates *difficulty by path-finding*. The sim must make the three
navigation mechanics directly comparable, both by playing and by headless measurement.

## world

- 2D plane 1600x1000 world units, entry gate on the left, exit gate on the right (y seeded).
- a seeded, time-varying divergence-free turbulence field (curl of value noise) pushes the ship
  everywhere on the map. This is the core difficulty source.
- scale flavor: HUD converts hyper-distance travelled to real-space distance via constant k.

## ship & costs (danger per README)

- thrust + turn + retro controls, linear drag, turbulence adds acceleration.
- hull: wears at a rate proportional to turbulence acceleration above an absorb threshold.
- energy: idle drain (hyperspace keeps systems alive), thrust drain, buoy drops;
  exit gate costs energy to open — arriving broke = stranded.
- lose on hull 0, energy 0, time limit; win on reaching exit gate with >= open cost.

## modes (checkboxes, combinable live)

Each mode produces a *turbulence damp scale* in [0..1]; active modes combine by min().

1. **beacons** — both gates emit a narrow light cone toward each other. Inside a cone the
   turbulence is damped to a floor (calm corridor) and mild beam pressure centers the ship on
   the axis. Challenge: the corridor is narrow and the field shoves you out of it.
2. **guide line** — a seeded bezier curve between the gates is a stable valley: turbulence
   scales up linearly with distance from the curve (full force beyond falloff), and a small
   valley-slope pull restores toward the curve. Challenge: the curve is longer than the
   straight line and the valley is soft.
3. **buoys** (the "other" mode) — the ship carries a limited stock of stabilizer buoys
   (Space to drop, costs energy). Each buoy calms turbulence in a radius around it.
   Challenge: build your own path under resource pressure — classic breadcrumb mechanic.

## tunables exposed in UI (for difficulty investigation)

turbulence strength, beam half-angle, guide falloff, seed. Modes toggle live.

## measurement

`experiments/difficulty.js` (node, headless): a naive autopilot flies each mode config
(raw / beacons / guide / buoys / all) over N seeds, fixed dt. Record win rate, failure causes,
time, hull wear, turbulence exposure. Results go to `experiments/logs/` and quantify how much
each mechanic reduces path-finding difficulty.

## files

- `field.js` — seeded value noise, curl turbulence force (node-guarded exports)
- `sim.js` — headless state + step, modes, costs, outcomes (node-guarded exports)
- `render.js` — canvas drawing of field, beams, guide valley, buoys, gates, ship, HUD
- `main.js` — DOM wiring, input, frame loop
- `index.html` — canvas + control panel, classic script tags, file:// friendly
- `experiments/difficulty.js` + `experiments/logs/difficulty-0.1.0.md`
